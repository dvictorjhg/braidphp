01 / Overview

Know what the framework does before you write code.

This guide stays close to the repository: the source under src/, the Example application, the PHPUnit suite, Composer metadata, Docker files, and the CI workflow.

What BraidPHP is

Attribute-driven routing plus a small runtime.

BraidPHP combines module composition, route scanning, immutable HTTP message objects, and a lightweight TCP listener. Dependency injection and provider storage come from dvictorjhg/php-injector.

Runtime model

One request at a time, by design.

App::listen() accepts a socket connection, parses one HTTP request, resolves one route action, writes one response, and closes the client. There is no worker pool or async event loop in this repository.

Prerequisites
  • PHP ^8.4
  • Composer
  • A second terminal for curl while the server keeps running
Explicit limitations
  • No middleware pipeline
  • No multi-process runtime or event loop
  • No request factory interfaces beyond the StreamFactory helper
  • No templating, ORM, or session abstraction in this repository
02 / First application

Build the smallest working app from an empty directory.

This walkthrough creates only the files the framework needs: composer.json, a PSR-4 src/ tree, one module, one controller, one provider, and a front controller that starts App::listen().

01

Create the project and install BraidPHP.

Start with a composer.json that declares PHP ^8.4, requires the package, and maps the App namespace to src/.

{
    "name": "acme/hello-braid",
    "require": {
        "php": "^8.4",
        "dvictorjhg/braidphp": "^1.0"
    },
    "autoload": {
        "psr-4": {
            "App\\": "src/"
        }
    }
}
Runcomposer install
02

Add one provider and one controller.

The provider is a plain PHP class. The controller uses a class prefix and a GET route that reads the captured :name parameter from the immutable request copy.

// src/Greeter.php
<?php

declare(strict_types=1);

namespace App;

final class Greeter
{
    public function greeting(string $name): string
    {
        return "Hello $name!";
    }
}

// src/GreetingController.php
<?php

declare(strict_types=1);

namespace App;

use dvictorjhg\braidphp\Router\Attributes\Get;
use dvictorjhg\braidphp\Router\Attributes\Route;
use dvictorjhg\braidphp\Router\Http\Request;

#[Route(path: '/api')]
final class GreetingController
{
    public function __construct(private Greeter $greeter)
    {
    }

    #[Get('/hello/:name', pathMatch: 'full')]
    public function hello(Request $request): string
    {
        return $this->greeter->greeting($request->getRouteParam('name') ?? '');
    }
}

04

Create the front controller and make a request.

The entry point follows the same boot sequence as Example/index.php: autoload, bootstrap the root module, then listen on SERVER_ADDRESS and SERVER_PORT with defaults.

// index.php
<?php

declare(strict_types=1);

require_once __DIR__ . '/vendor/autoload.php';

use App\AppModule;
use dvictorjhg\braidphp\Core\App;

$app = new App();
$app->bootstrapModule(new AppModule());

$address = (string) getenv('SERVER_ADDRESS') ?: '0.0.0.0';
$port = (string) getenv('SERVER_PORT') ?: '8000';

$app->listen(address: $address, port: $port);
Terminal 1php index.php Terminal 2curl http://127.0.0.1:8000/api/hello/Ada
!
What should happen

Run the server in one terminal and the curl request in a second terminal. The server prints "Server listening on 0.0.0.0:8000..." and the request returns "Hello Ada!". Every extra request is handled by the same process in sequence.

bootstrap example

Resolve startup services after routes exist.

Bootstrap entries are keyed by class name. Arrays become constructor arguments for that class, while prebuilt objects are left untouched.

<?php

declare(strict_types=1);

use dvictorjhg\braidphp\Core\App;
use dvictorjhg\braidphp\Core\Attributes\Module;
use dvictorjhg\braidphp\Router\HttpModule;

require_once __DIR__ . '/vendor/autoload.php';

final class BootstrapService
{
}

final class ExistingService
{
}

#[Module(
    imports: [HttpModule::class],
    bootstrap: [
        BootstrapService::class => [],
        ExistingService::class => new ExistingService(),
    ],
)]
final class StartupModule
{
}

$app = new App();
$app->bootstrapModule(new StartupModule());

04 / Routing

Declare routes where the controller lives.

RouteScanner reads class and method attributes, Router walks the resulting tree depth-first, and App::handleRequest() attaches the matched parameters to a request copy.

Example/Controllers/GreeterComponent.php ROUTES 
<?php

namespace dvictorjhg\braidphp\Example\Controllers;

use dvictorjhg\braidphp\Router\Attributes\Get;
use dvictorjhg\braidphp\Router\Attributes\Route;
use dvictorjhg\braidphp\Router\Http\HttpMethod;
use dvictorjhg\braidphp\Router\Http\Request;
use dvictorjhg\braidphp\Router\Http\Response;

#[Route(path: '/api')]
final class GreeterComponent
{
    #[Route(
        httpMethod: HttpMethod::GET->value | HttpMethod::POST->value,
        path: '/hi/:name'
    )]
    public function hi(Request $request): string
    {
        $name = $request->getRouteParam('name') ?? '';
        return "Hi $name!";
    }

    #[Get('/hello/:name')]
    public function greet(Request $request): string
    {
        $name = $request->getRouteParam('name') ?? '';
        return 'Hello ' . $name . '!';
    }

    #[Get('/hello')]
    public function greetQueryParam(Request $request): Response
    {
        $name = $request->getQueryParams()['name'] ?? null;
        return \is_string($name) && $name !== ''
            ? new Response(body: 'Hello ' . $name . '!')
            : new Response(400);
    }
}

Equivalent declarations

One GET route, two valid forms.

The #[Get] shortcut and generic #[Route] attribute resolve to the same GET route. Choose one declaration for a route.

#[Get('/hello/:name', pathMatch: 'full')]
public function hello(Request $request): string
{
    return 'Hello ' . ($request->getRouteParam('name') ?? '') . '!';
}
#[Route(
    httpMethod: HttpMethod::GET,
    path: '/hello/:name',
    pathMatch: 'full',
)]
public function hello(Request $request): string
{
    return 'Hello ' . ($request->getRouteParam('name') ?? '') . '!';
}
!
Do not stack both attributes

Stacking both on one method creates duplicate route entries for the same path and makes precedence harder to reason about.

Programmatic matcher

Return UrlMatcherResult or return null.

Programmatic routes can use a custom matcher instead of a path string, but not both at once.

<?php

declare(strict_types=1);

use dvictorjhg\braidphp\Router\Classes\Route;
use dvictorjhg\braidphp\Router\Classes\UrlMatcherResult;
use dvictorjhg\braidphp\Router\Http\HttpMethod;
use dvictorjhg\braidphp\Router\Http\Response;
use dvictorjhg\braidphp\Router\Router;

require_once __DIR__ . '/vendor/autoload.php';

final class HealthComponent
{
    public function status(): Response
    {
        return new Response(body: 'ok');
    }
}

$router = new Router();

$router->setRoutes(new Route(
    httpMethod: HttpMethod::GET,
    matcher: static function (array $parts, Route $route): ?UrlMatcherResult {
        return ($parts[0] ?? null) === 'health'
            ? new UrlMatcherResult(['health'])
            : null;
    },
    action: [HealthComponent::class, 'status'],
));

$matched = $router->processRoutes(new \dvictorjhg\braidphp\Router\Http\Request(
    method: HttpMethod::GET,
    uri: '/health',
));

echo $matched !== null ? 'matched' : 'not matched';
05 / HTTP messages

Treat HTTP state as immutable values.

Request and Response extend a shared Message base class. Uri and Stream implement the relevant PSR interfaces directly, and with* methods return changed copies.

REQUEST

Request

Request implements RequestInterface, parses query parameters on construction, injects a Host header from the URI when needed, and stores route parameters only on withRouteParams() copies.

<?php

declare(strict_types=1);

use dvictorjhg\braidphp\Router\Http\HttpMethod;
use dvictorjhg\braidphp\Router\Http\Request;

require_once __DIR__ . '/vendor/autoload.php';

$request = new Request(
    method: HttpMethod::GET,
    uri: 'http://example.test:8080/hello?name=Ada',
    body: '',
);

$routed = $request
    ->withRouteParams(['scope' => 'demo'])
    ->withHeader('X-Trace', 'one')
    ->withAddedHeader('X-Trace', 'two');

echo ($request->getRouteParam('scope') ?? 'none') . "\n";
echo $routed->getHeaderLine('x-trace') . "\n";
echo $routed->getHeaderLine('host') . "\n";
Expected outputnone one,two example.test:8080
RESPONSE

Response

Response implements ResponseInterface, supplies known reason phrases automatically, and writes Content-Type plus Content-Length during string serialization when those headers were not supplied.

<?php

declare(strict_types=1);

use dvictorjhg\braidphp\Router\Http\Response;

require_once __DIR__ . '/vendor/autoload.php';

$response = new Response(
    statusCode: 201,
    body: 'welcome',
);

echo $response->getStatusCode() . PHP_EOL;
echo $response->getReasonPhrase() . PHP_EOL;
echo (string) $response;

Component Actual behavior Notes
Request Implements RequestInterface, not ServerRequestInterface. Query params come from the URI; route params are BraidPHP-specific helpers.
Response Wraps the body as a stream and serializes itself to a wire-format HTTP response string. Explicit Content-Length and Content-Type headers are preserved.
Uri Implements UriInterface, normalizes scheme/host/query data, and keeps derived path parts in sync. Path parameters are matched against getPathParts().
Stream Implements StreamInterface over native PHP stream resources. Detached streams reject tell/read/write/seek/eof/getContents operations.
StreamFactory Helper for creating PSR streams from scalars, native PHP stream resources, stringable objects, or existing streams. This repository does not ship PSR-17 request or response factory interfaces.

06 / Runtime lifecycle

Follow the request from the socket to the controller result.

The request lifecycle is short enough to read end-to-end in App.php, RequestParser.php, Router.php, and the Example controllers.

01Acceptstream_socket_accept()
02ParseRequest::fromResource()
03MatchRouter::processRoutes()
04ResolveInjector::inject()
05WriteResponse::__toString()
01

Raw socket to Request

RequestParser reads the request line and headers from the stream, then reads the body according to Content-Length when it is present. An empty client stream yields no request.

02

Routing and parameter capture

Router compares the request method against the HttpMethod enum, walks the registered routes in order, and collects decoded :name path parameters into RouteMatch::params.

03

Controller invocation

App::handleRequest() clones the matched request with route params and invokes the route action through PHPInjector. The request copy is passed as an explicit argument keyed by its class name.

04

Result conversion and failures

A Response is returned unchanged. Null, scalars, native PHP stream resources, existing PSR streams, and stringable objects become Response(200, [], body). Arrays raise AppException, while objects that are neither stringable nor streams raise InvalidArgumentException during body conversion. The socket loop converts uncaught throwables into a 500 response body starting with “Server Error:”.
